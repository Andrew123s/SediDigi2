# SediDigi/opencv_build

Builds OpenCV with full CUDA support on Jetson Orin Nano devices.

## Motivation

The NVIDIA JetPack repository provides OpenCV (4.8.0) with CUDA support in the C++ libraries,
but the Python bindings are compiled **without** CUDA. This means `cv2.cuda` is unavailable
in Python out of the box.

This project builds OpenCV entirely from source — libraries, Python bindings, GStreamer support,
and CUDA acceleration — as a single consistent unit. Building OpenCV from source takes
approximately 1-2 hours. The result can optionally be packaged as a portable tarball
for transfer to another Jetson, avoiding a rebuild on this device.

## Files

- **build_opencv.sh** — Build script: compiles OpenCV on the source device; optionally creates a portable tarball
- **install_opencv_portable.sh** — Install script: extracts the tarball on the target device and sets up the environment
- **opencv-env.sh** — Template environment file, auto-generated by the other scripts with correct paths
- **test_gpu_vs_cpu.py** — Benchmark comparing GPU-accelerated vs CPU OpenCV operations
- **test_gpu_vs_cpu_opt.py** — Optimized benchmark with pre-created objects and GPU kernel timing via CUDA Events

## Requirements

- Jetson Orin Nano with JetPack (Ubuntu 22.04, aarch64)
- sudo access on the build machine (used automatically for dependency installation)
- CUDA toolkit and cuDNN installed on the build machine
- ~10 GB free disk space for the build

> **Note:** If the OpenCV source already exists in the build directory,
> the download is skipped automatically.

## Usage

### 1. Build (on the source Jetson)

```bash
./build_opencv.sh                          # builds the latest OpenCV version
./build_opencv.sh 4.10.0                   # or specify a version explicitly
./build_opencv.sh --portable               # build and create a portable tarball
./build_opencv.sh --portable 4.10.0        # do both with specific version
```

The script will:
- Install build dependencies via `sudo apt-get` (needs sudo password)
- Clone OpenCV source to `~/opencv/src` and `~/opencv/contrib`
- Configure and compile with CUDA support (arch 8.7, takes ~1-2 hours)
- Install to `~/opencv-install`
- Generate `opencv-env.sh` inside the install directory
- Optionally create `~/opencv-portable.tar.gz` (with `--portable`)

### 2. Transfer (optional)

Only needed if `--portable` was used. Transfer the resulting tarball to the target device
using any method (USB, network, etc.).

### 3. Install (on the target Jetson)

```bash
chmod +x install_opencv_portable.sh
./install_opencv_portable.sh /path/to/opencv-portable.tar.gz
```

The script will:
- Extract the tarball to `~/opencv-install`
- Generate `opencv-env.sh` with correct paths
- Verify the installation (libraries, pkg-config, Python bindings, cmake)

### 4. Activate environment

```bash
source ~/opencv-install/opencv-env.sh
```

To make this permanent, add to `~/.bashrc`:

```bash
if [[ -f "${HOME}/opencv-install/opencv-env.sh" ]]; then
    source "${HOME}/opencv-install/opencv-env.sh"
fi
```

## Verification

After activating the environment, verify the installation:

```bash
python3 -c "import cv2; print(cv2.__version__)"
pkg-config --modversion opencv4
ls ~/opencv-install/lib/libopencv*
```

Run the GPU vs CPU benchmark to confirm that CUDA acceleration works:

```bash
python3 test_gpu_vs_cpu.py            # simple benchmark
python3 test_gpu_vs_cpu_opt.py        # optimized with GPU kernel timing
```

## Notes

### GPU vs CPU Performance

GPU acceleration does not always outperform the CPU. The total GPU time includes
upload (host→device) and download (device→host) of image data (~24 MB for 4K BGR).
For fast operations like Resize, CvtColor, or Threshold, this transfer overhead dominates
and makes GPU execution slower overall.

Compute-intensive operations (Gaussian Blur, Affine Warp) benefit most from GPU
parallelism. The optimized benchmark (`test_gpu_vs_cpu_opt.py`) measures the pure
GPU kernel time separately using CUDA Events, showing the actual compute speedup
without transfer overhead.

### Pipelines

The real advantage of GPU acceleration lies in **chaining multiple operations** while
keeping data on the device. When processing a pipeline (e.g. BGR→Lab→Blur→Resize→BGR),
the GPU performs all steps sequentially without transferring results back to the host.
This avoids repeated upload/download overhead and can yield 2x or higher speedup even
for operations that are not individually faster on the GPU.

### Python vs C++

The benchmarks are written in Python for ease of use. A C++ implementation would reduce
wrapper overhead by ~10-15% for round-trip (GPU total) times. Additionally, C++ allows
using CUDA streams to overlap upload, computation, and download — which could further
improve pipeline performance by 30-50%. For benchmarking purposes, Python is sufficient.
For production pipelines with strict latency requirements, C++ is recommended.

### Benchmark Scripts

- `test_gpu_vs_cpu.py` — Simple benchmark, measures total round-trip time (upload + process + download)
- `test_gpu_vs_cpu_opt.py` — Optimized benchmark with pre-created filter/detector objects,
  separate GPU kernel timing via CUDA Events, and a pipeline benchmark demonstrating the
  benefit of chaining multiple operations on the GPU
